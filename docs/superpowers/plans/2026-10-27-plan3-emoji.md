# Plan 3 — iOS emoji screen

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (inline, as plans 1–2). Steps use checkbox (`- [ ]`) syntax.

**Goal:** the emoji screen looks and scrolls like iOS 27 (reference: user's simulator screenshot, 2026-10-27).

**Architecture:** in the iOS style `EmojiPalettesView` swaps HeliBoard's pager (vertical pages per category, tab strip on top, keyboard bottom row) for one horizontal `RecyclerView` with one item per iOS section. Each item is a sticky section title above an `EmojiPageKeyboardView` whose `DynamicGridKeyboard` lays keys out column-major in 5 rows, so key drawing, skin-tone popups and recents keep HeliBoard's code. A new `IosEmojiBottomRow` replaces the bottom-row keyboard: ABC label, category icons with a round highlight for the current section, delete with auto-repeat. Pure logic lives in `latin/ios/IosEmojiLayout.kt`.

**Spec:** `docs/superpowers/specs/2026-10-26-ios-keyboard-design.md` (emoji screen: grid by categories, category icons at the bottom plus ABC/back, no HeliBoard tabs).

## Global Constraints

- iOS style only; stock styles keep HeliBoard's emoji screen.
- Sections in iOS order: Frequently used, Smileys & People (HeliBoard SMILEYS + PEOPLE merged), Animals & Nature, Food & Drink, Activity, Travel & Places, Objects, Symbols, Flags (if the font has them). No emoticons section.
- 5 rows; section titles are small grey caps, translated ru / kk / en; the current section title sticks to the left edge until the next section pushes it away.
- No strip above the emoji screen (no tab strip, no suggestion strip); panel height equals the letter keyboard's.
- Emoji search is NOT in this plan (needs emoji dictionaries ru/en/kk — separate step, if the user wants it).

## Review Focus

1. Recents empty on first launch — section hidden or no crash, scrolling starts at Smileys.
2. Adding a recent while the recents section is on screen must not reflow it under the finger (HeliBoard's pending-keys behaviour).
3. Delete held down repeats and stops on release/cancel, also when the finger leaves the button.
4. Switching theme to a stock style and back rebuilds the emoji screen correctly (keyboard cache cleared).
5. Long-press skin-tone popup stays inside the screen near the left/right edge.
